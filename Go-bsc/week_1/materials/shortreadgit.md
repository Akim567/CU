# Git и GitLab — Краткий справочник

## Основные концепции

**Git** — система контроля версий для отслеживания изменений в коде и командной работы.

**Репозиторий** — директория с историей всех изменений проекта (локальный или удалённый).

**Коммит** — зафиксированное изменение в репозитории Git ("снимок" состояния проекта).

**Ветка** — независимая линия разработки для новых функций или экспериментов.

**Merge** — процесс объединения изменений из одной ветки в другую.

## Основные команды

### Инициализация и базовые операции
```bash
git init                    # Создать репозиторий
git status                  # Посмотреть состояние файлов
git add <файл>             # Добавить файл в staging area
git add .                  # Добавить все файлы (осторожно!)
git commit -m "сообщение"  # Создать коммит
git log                    # История коммитов
```

### Работа с ветками
```bash
git branch                 # Список веток
git branch <имя>          # Создать ветку
git checkout <ветка>      # Переключиться на ветку
git checkout -b <имя>     # Создать и переключиться на ветку
git merge <ветка>         # Слить ветку в текущую
git branch -d <имя>       # Удалить ветку
```

### Работа с удалённым репозиторием
```bash
git clone <URL>           # Клонировать репозиторий
git remote add origin <URL>  # Добавить удалённый репозиторий
git push origin <ветка>   # Отправить изменения
git pull origin <ветка>   # Получить изменения
```

## Состояния файлов

1. **Untracked** — новый файл, который Git ещё не отслеживает
2. **Modified** — файл изменён, но не подготовлен для коммита
3. **Staged** — файл в области подготовки (staging area), готов к коммиту
4. **Committed** — изменения сохранены в репозитории

**Staging area (индекс)** — промежуточная область, где фиксируются изменения перед коммитом.

## Хорошие сообщения коммитов

**Советы:**
- Краткое описание что и зачем изменено
- Глагол от 3-го лица: "добавлена", "исправлен", "удалены"
- До 50 символов в первой строке
- Избегать общих фраз: "всё исправлено", "что-то изменено"

**Примеры:**
- ✅ `git commit -m "Добавлена функция поиска пользователей"`
- ✅ `git commit -m "Исправлен баг с авторизацией"`
- ❌ `git commit -m "всё работает"`

## Ветки и слияние

### Принципы работы с ветками
- **main** — основная ветка с рабочим кодом
- **feature-ветки** — для разработки новых функций
- Изменения сначала делают в отдельной ветке, потом сливают в main

### Пример работы с ветками
```bash
git checkout -b add-user-search    # создать ветку для новой функции
# ... внести изменения ...
git add .
git commit -m "Добавлена функция поиска пользователей"
git checkout main                  # вернуться на основную ветку
git merge add-user-search         # слить изменения
git branch -d add-user-search     # удалить ветку после слияния
```

## Разрешение конфликтов

**Что происходит при конфликте:**
1. Git помечает конфликтующие участки в файле специальными маркерами
2. Разработчик вручную редактирует файл, выбирая нужные изменения
3. Удаляет служебные строки (`<<<<<<<`, `=======`, `>>>>>>>`)
4. Выполняет `git add` и `git commit`

**Пример конфликта в файле:**
```
func addSlices(a, b []int) []int {
<<<<<<< HEAD
    // Версия из текущей ветки
    return append(a, b...)
=======
    // Версия из сливаемой ветки  
    result := make([]int, len(a)+len(b))
    copy(result, a)
    copy(result[len(a):], b)
    return result
>>>>>>> feature-branch
}
```

## GitLab: Командная работа

### Merge Request (MR) — процесс командной разработки
1. Создать ветку для новой функции
2. Внести изменения и закоммитить
3. Отправить ветку: `git push origin feature-branch`
4. Создать MR в веб-интерфейсе GitLab
5. Коллеги делают ревью кода
6. После одобрения — слияние в основную ветку

### README.md — лицо проекта
**Стандартные разделы:**
- Название и описание проекта
- Установка и запуск
- Примеры использования  
- Вклад в проект (Contributing)
- Автор и лицензия

### .gitignore — игнорируемые файлы
**Для Go проектов:**
```
# Скомпилированные бинарники
*.exe
*.dll
*.so

# Временные файлы и логи
*.tmp
*.log

# IDE файлы
.idea/
.vscode/

# Go модули (vendor)
vendor/
```
