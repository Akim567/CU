# Лекция 5: Пакеты, функции и дженерики

## Зачем нужна организация кода?

Любой серьёзный проект состоит из многих файлов и имеет сложную структуру. По мере роста кодовой базы возникают вопросы: как организовать код так, чтобы он оставался понятным и поддерживаемым? Как обеспечить повторное использование компонентов? Как сделать код гибким и типобезопасным одновременно?

Go предлагает следующие ключевые механизмы для решения этих задач:

- **Пакеты** — механизм организации кода и управления областью видимости
- **Модули** — управление зависимостями, версиями и границами проекта
- **Функции** — основные строительные блоки логики программы
- **Дженерики** — возможность писать код, работающий с разными типами, не теряя типобезопасности

В этой лекции мы разберём все эти темы, научимся их эффективно комбинировать и поймём, когда какой инструмент лучше применять.

## Пакеты: модули и области видимости

Пакет в Go — это набор исходных файлов с одинаковым объявлением `package` в одном каталоге: они компилируются вместе. Это основная единица организации и переиспользования кода.

### Различие между пакетом и модулем

**Модуль** — коллекция пакетов, которая публикуется, распространяется и версионируется как единое целое. Модуль определяется наличием файла `go.mod` в корневой директории.

**Пакет** — директория с исходными файлами Go, объединёнными под одним пространством имён, задаваемом объявлением `package`.

Модуль может содержать множество пакетов:

```
example.com/my-module
├── go.mod
├── cmd/        # точки входа (каждая подпапка задает пакет main)
│   └── app/
│       └── main.go
├── internal/   # пакеты, доступные только внутри этого модуля
│   ├── config/
│   └── server/
└── pkg/        # общедоступные пакеты (распространённый паттерн)
    ├── database/
    └── logger/
```

Эта структура отражает типичную организацию модуля Go. Обратите внимание, как разные компоненты системы разделены по своему назначению: точки входа в `cmd`, внутренние компоненты в `internal`, и публичные пакеты в `pkg`. Такое разделение помогает поддерживать чистоту архитектуры и понятные границы между компонентами. Более подробно рекомендуемую структуру проекта мы рассмотрим в будущих лекциях.

### Объявление пакета

Каждый исходный файл Go должен начинаться с объявления пакета, к которому он принадлежит (это объявление называется _package clause_):

```go
package mypackage
```

Особый случай — объявление пакета `main`. Пакеты с таким объявлением служат точкой входа для исполняемых программ и содержат функцию `main`:

```go
package main

func main() {
    // Начало выполнения программы
}
```

### Импорт пакетов

Для использования кода из других пакетов используется оператор `import`:

```go
package main

import (
	"fmt"                        // стандартный пакет
	"my-module/internal/config"  // внутренний пакет
	"github.com/sirupsen/logrus" // внешний пакет
)

func main() {
	cfg, err := config.Load()
	if err != nil {
		logrus.WithError(err).Fatalln("loading config")
	}
	fmt.Printf("Config loaded: %+v\n", cfg)
}
```

### Видимость и экспорт

В Go видимость идентификаторов (переменных, функций, типов) определяется **регистром первой буквы**:

- **Экспортируемые** (видимые из других пакетов) идентификаторы начинаются с **заглавной буквы**
- **Неэкспортируемые** (видимые только внутри пакета) — с **маленькой буквы**

```go
package user

// Экспортированный тип (виден извне)
type User struct {
	Name string // экспортированное поле
	age  int    // неэкспортированное поле
}

// Экспортированная функция
func NewUser(name string, age int) User {
    return User{
        Name: name,
        age:  age,
    }
}

// Неэкспортированная функция
func validate(u User) bool {
    return u.Name != "" && u.age > 0
}
```

В этом примере мы видим ключевой принцип инкапсуляции в Go. Структура `User` экспортирована и доступна извне пакета, но поле `age` скрыто. Это создаёт контролируемый API: клиентский код должен использовать функцию `NewUser` для создания объектов, что позволяет гарантировать валидность данных. Функция `validate` не экспортирована, поэтому может использоваться только внутри кода самого пакета.

Код из других пакетов может использовать только экспортированные сущности:

```go
package main

import (
    "fmt"
    "my-module/user"
)

func main() {
	u := user.NewUser("Alice", 30)

	fmt.Println(u.Name) // доступно

	fmt.Println(u.age)  // ошибка компиляции
	user.validate(u)    // ошибка компиляции
}
```

Здесь демонстрируется использование пакета извне. Клиентский код может создать пользователя через экспортированный конструктор и обратиться к экспортированному полю `Name`, но попытки получить доступ к неэкспортированному полю `age` или вызвать внутреннюю функцию `validate` приведут к ошибкам компиляции. Такой механизм защищает внутреннюю реализацию пакета от непредвиденных изменений.

### Именование и избегание "статтеринга"

При проектировании пакетов следует избегать "статтеринга" (stuttering) - повторения имени пакета в именах экспортируемых идентификаторов. При импорте имя пакета уже служит префиксом:

Плохо делать так:

```go
package user

func UserCreate() { /* ... */ }
func UserDelete() { /* ... */ }
```

При использовании этих идентификаторов в других пакетах предстоит писать так: `user.UserCreate()` — что является избыточным.

Лучше делать так:

```go
package user

func Create() { /* ... */ }
func Delete() { /* ... */ }
```

Тогда в других пакетах предстоит писать так: `user.Create()` — что является понятным и не избыточным.

### Пакет `internal`

Go предоставляет особый механизм для ограничения доступа к пакетам модуля — любой пакет внутри директории `internal` доступен только для пакетов этого модуля:

```
my-module/
├── internal/
│   └── database/  // доступен только внутри my-module
├── api/
│   └── handler.go // может импортировать my-module/internal/database
└── client/
    └── main.go    // может импортировать my-module/internal/database
```

Пакет `my-module/internal/database` не может быть импортирован из другого модуля.

### Функция `init`

Каждый пакет может содержать функции `init`, которые выполняются на стадии инициализации пакета:

```go
package database

import "log"

var db *Database

func init() {
    // Выполнится один раз при импорте пакета
    log.Println("Initializing database...")
    db = &Database{}
}

type Database struct {
    // ...
}
```

Функция `init` - особая в Go. Она выполняется при инициализации программы, если пакет вошёл в сборку (то есть был импортирован). Функция часто используется для настройки глобальных переменных или регистрации драйверов. В этом примере мы инициализируем глобальный экземпляр базы данных. Однако будьте осторожны с `init`: код в нём выполняется неявно и может усложнить тестирование. Для сложной инициализации с возможными ошибками лучше использовать явные конструкторы.

Важные особенности `init`:
- Может быть несколько функций `init` в одном пакете
- Выполняются после инициализации глобальных переменных
- Порядок выполнения: сначала в импортируемых пакетах, затем в текущем
- Не принимают параметров и ничего не возвращают

### Циклические зависимости

Go запрещает циклические импорты пакетов. Например, если пакет `A` импортирует пакет `B`, а пакет `B` импортирует пакет `A`, компилятор выдаст ошибку:

```
import cycle not allowed
```

Для разрешения циклических зависимостей обычно используют одну из стратегий:
1. Выделение общего кода в третий пакет
2. Использование интерфейсов вместо прямых зависимостей
3. Переосмысление архитектуры компонентов

## Продвинутое использование функций

Базовый синтаксис функций мы рассмотрели в первой лекции. Теперь перейдём к более продвинутым техникам, которые делают код более гибким и элегантным.

### Функции как значения

Функции в Go являются значениями первого класса, то есть их можно:
- Присваивать переменным
- Передавать в качестве аргументов
- Возвращать из других функций

```go
package main

import "fmt"

func main() {
	// Функция как переменная
	add := func(a, b int) int {
		return a + b
	}

	// Передача функции как аргумента
	result := compute(5, 3, add)
	fmt.Println("5 + 3 =", result) // 8

	// Другая функция в тот же параметр
	result = compute(5, 3, func(a, b int) int {
		return a * b
	})
	fmt.Println("5 * 3 =", result) // 15
}

// Функция, принимающая другую функцию
func compute(a, b int, operation func(int, int) int) int {
	return operation(a, b)
}
```

Этот пример демонстрирует мощь функций первого класса в Go. Мы можем присваивать функции переменным (`add`), передавать их в качестве аргументов (`compute(5, 3, add)`) и даже создавать на месте анонимные функции. Такая гибкость позволяет реализовать элегантные паттерны функционального программирования, например, стратегии, декораторы и колбэки, не усложняя при этом структуру программы.

### Функциональные опции для конфигурации

Если функция или конструктор имеют много необязательных параметров, один из традиционных подходов — создание структуры с параметрами. Однако также есть элегантный паттерн "функциональные опции":

```go
package server

import "time"

type Server struct {
    addr         string
    readTimeout  time.Duration
    writeTimeout time.Duration
    maxConn      int
}

// Option — функциональный тип для настройки сервера
type Option func(*Server)

// WithReadTimeout устанавливает время ожидания чтения
func WithReadTimeout(d time.Duration) Option {
    return func(s *Server) {
        s.readTimeout = d
    }
}

// WithWriteTimeout устанавливает время ожидания записи
func WithWriteTimeout(d time.Duration) Option {
    return func(s *Server) {
        s.writeTimeout = d
    }
}

// WithMaxConnections устанавливает максимальное число соединений
func WithMaxConnections(n int) Option {
    return func(s *Server) {
        s.maxConn = n
    }
}

// NewServer создаёт сервер с опциями
func NewServer(addr string, opts ...Option) *Server {
    // Значения по умолчанию
    srv := &Server{
        addr:         addr,
        readTimeout:  30 * time.Second,
        writeTimeout: 30 * time.Second,
        maxConn:      100,
    }
    
    // Применяем все переданные опции.
    for _, opt := range opts {
        opt(srv)
    }
    
    return srv
}
```

Использование:

```go
func main() {
    // Только с обязательным параметром
    srv1 := server.NewServer(":8080")
    
    // С дополнительными опциями
    srv2 := server.NewServer(":9090",
        server.WithReadTimeout(10*time.Second),
        server.WithMaxConnections(1000),
    )
    
    // ...
}
```

### Замыкания и управление ресурсами

Замыкание — это функция, которая захватывает переменные из внешнего лексического окружения.

```go
package main

import "fmt"

func main() {
    // Создаём счётчик
    counter := newCounter()
    
    fmt.Println(counter()) // 1
    fmt.Println(counter()) // 2
    fmt.Println(counter()) // 3
}

// newCounter создаёт и возвращает функцию-счётчик
func newCounter() func() int {
    count := 0
    
    // Возвращаемая функция замыкает переменную count
    return func() int {
        count++
        return count
    }
}
```

В этом примере мы видим замыкание в действии. Функция `newCounter` создаёт локальную переменную `count` и возвращает функцию, которая имеет доступ к этой переменной даже после завершения `newCounter`. Каждый вызов `counter()` увеличивает значение `count` и возвращает его. Важно понимать, что это не просто функция, а функция вместе с замкнутым состоянием — каждый вызов `newCounter()` создаст новую независимую переменную `count` и функцию, работающую с ней.

Распространённый пример использования замыканий — управление закрытием ресурсов для последующего использования с оператором `defer`:

```go
func openDatabase() (db *Database, cleanup func(), err error) {
    db, err = sql.Open("postgres", "...")
    if err != nil {
        return nil, nil, err
    }
    
    // Возвращаем функцию для освобождения ресурсов
    cleanup = func() {
        db.Close()
    }
    
    return db, cleanup, nil
}

func main() {
    db, cleanup, err := openDatabase()
    if err != nil {
        log.Fatal(err)
    }
    defer cleanup() // Гарантируем закрытие ресурса
    
    // Работаем с БД...
}
```

### Ошибки

При работе с ошибками в Go важно сохранять контекст - какие ошибки нам встретились по пути и откуда они взялись (по стеку вызовов). Стандартный пакет `errors` предоставляет инструменты для этого:

```go
package main

import (
    "errors"
    "fmt"
)

var (
    ErrNotFound = errors.New("not found")
)

func findUser(id string) (string, error) {
    return "", ErrNotFound
}

func getUserName(id string) (string, error) {
    name, err := findUser(id)
    if err != nil {
        // Оборачиваем ошибку, сохраняя оригинал с помощью %w
        return "", fmt.Errorf("getUserName: %w", err)
    }
    return name, nil
}

func main() {
    name, err := getUserName("123")
    if err != nil {
        // Проверяем, содержит ли ошибка в цепочке ошибок ErrNotFound
        if errors.Is(err, ErrNotFound) {
            fmt.Println("Пользователь не найден")
        } else {
            fmt.Println("Другая ошибка:", err)
        }
    }
}
```

Этот пример показывает современный подход к обработке ошибок в Go. Обратите внимание на ключевые моменты:
1. Мы используем `%w` в `fmt.Errorf` для оборачивания ошибки с сохранением оригинала
2. Затем используем `errors.Is` для проверки, содержит ли цепочка ошибок определенную ошибку
3. Это позволяет добавлять контекст к ошибкам при их распространении вверх по стеку вызовов
4. Вызывающий код может проверить тип ошибки и выбрать соответствующую обработку
5. Оборачивать в цепочку с помощью `%w` можно сколько угодно ошибок. В `fmt.Errorf` можно использовать несколько `%w` - все ошибки будут доступны для `errors.Is`. Однако для склейки нескольких ошибок более явным подходом является использование `errors.Join`
6. Стоит также обратить внимание на то, что по конвенции сообщением ошибки является строка с маленькой буквы, без точки на конце и без повторения имен пакетов/функций - контекст добавляется при обёртке

Такой подход делает отладку проще, а код обработки ошибок — чище и информативнее. В этом и заключается сравнительное преимущество подхода "ошибка как значение".

## Дженерики: обобщённые типы

Дженерики (обобщённые типы) — относительно новая возможность в Go, появившаяся в версии 1.18. Они позволяют писать код, который работает с разными типами данных, сохраняя при этом статическую типобезопасность.

### Что такое дженерики и зачем они нужны?

До появления дженериков в Go было два основных подхода к созданию обобщённых алгоритмов:

1. **Использование интерфейсов** — использование `interface{}` (`any`) и приведение типов
2. **Копирование кода для каждого типа** — приводит к дублированию и затрудняет сопровождение

Дженерики решают эти проблемы, позволяя писать код, параметризованный по типам.

### Синтаксис дженериков

Базовый синтаксис использования дженериков включает объявление параметров типа в квадратных скобках:

```go
// T - параметр типа
func Print[T any](value T) {
    fmt.Println(value)
}

// Использование
Print[int](42) // Явное указание типа
Print("Hello") // Компилятор сам выводит тип
```

В этом примере `T` — параметр типа, а `any` — ограничение, указывающее, что можно использовать любой тип. Мы объявляем функцию `Print`, которая может работать с аргументом любого типа. При вызове функции компилятор может сам вывести тип параметра из типа переданного аргумента, поэтому в большинстве случаев явное указание типа (`Print[int]`) не требуется (линтер скорее всего потребует убрать явное указание типа). Это делает код чище, сохраняя при этом все преимущества статической типизации.

### Ограничения типов (Constraints)

Параметры типа могут иметь ограничения, определяющие, какие типы допустимы:

```go
// Полное перечисление типов, с которыми работает функция (громоздко)
func Sum[T int | int32 | int64 | float32 | float64](a, b T) T {
    return a + b
}

// Более элегантное решение с вынесением интерфейса-ограничения
type Number interface {
    int | int32 | int64 | float32 | float64
}

func Sum[T Number](a, b T) T {
    return a + b
}
```

Среди стандартных пакетов уже определены некоторые полезные ограничения, например `cmp.Ordered` и предопределённый идентификатор `comparable`.

Также существует внешний пакет `golang.org/x/exp/constraints`, поставляемый отдельно:

```go
import "golang.org/x/exp/constraints"

// Функция работает с любыми целочисленными типами
func Min[T constraints.Integer](a, b T) T {
    if a < b {
        return a
    }
    return b
}
```

Ограничения типов — важнейшая часть дженериков в Go. Они позволяют указать, какие операции можно применять к параметрам типа. В первом примере мы ограничиваем `T` конкретным набором числовых типов, для которых определена операция сложения.

Во втором примере мы выносим это ограничение в интерфейс, что делает код более читаемым и переиспользуемым. Такой подход позволяет абстрагироваться от конкретных типов, сохраняя при этом строгую типизацию.

В третьем примере мы используем ограничение из пакета `golang.org/x/exp/constraints`, которое охватывает все целочисленные типы (`int`, `int8`, `int64`, `uint` и т.д.). Стандартные пакеты и `golang.org/x/exp/constraints` предоставляют и другие полезные ограничения, что избавляет нас от необходимости их повторного определения.

### Обобщённые типы данных

Не только функции, но и типы данных могут быть параметризованы:

```go
// Обобщённый стек
type Stack[T any] struct {
    items []T
}

func NewStack[T any]() *Stack[T] {
    return &Stack[T]{}
}

func (s *Stack[T]) Push(item T) {
    s.items = append(s.items, item)
}

func (s *Stack[T]) Pop() (T, error) {
    var zero T
    if len(s.items) == 0 {
        return zero, errors.New("stack is empty")
    }
    
    n := len(s.items) - 1
    item := s.items[n]
    s.items = s.items[:n]
    return item, nil
}

// Использование
func main() {
    // Стек строк
    stack := NewStack[string]()
    stack.Push("world")
    stack.Push("hello")
    
    s1, _ := stack.Pop()
    s2, _ := stack.Pop()
    fmt.Println(s2, s1) // "hello world"
    
    // Стек чисел
    numStack := NewStack[int]()
    numStack.Push(10)
    numStack.Push(20)
}
```

Этот пример демонстрирует одно из самых мощных применений дженериков — создание типобезопасных контейнеров данных. Мы реализуем классическую структуру данных "стек", которая может хранить элементы любого типа, сохраняя при этом строгую типизацию.

Обратите внимание на ключевые моменты:
1. Параметр типа `T` с ограничением `any` используется как в структуре, так и в методах
2. Конструктор `NewStack[T]()` возвращает типизированный стек (`*Stack[T]`)
3. При возврате нулевого значения создаётся переменная `var zero T` — это правильный идиоматический способ получить нулевое значение типа-параметра
4. При использовании создаются два разных стека с разными типами (`string` и `int`), каждый типобезопасен

До появления дженериков такая реализация требовала бы либо дублирования кода для каждого типа, либо использования интерфейсов и типовых утверждений, что снижало бы безопасность типов и производительность.

### Оператор ~: работа с подлежащими и определенными типами

Оператор `~` позволяет включать в ограничение все типы с указанным подлежащим типом (underlying type):

```go
type StringID string // Определенный тип StringID, подлежащий тип - string

// Без оператора ~ требуется точное совпадение типа: подойдёт только именно string
func join[T string](values []T, sep string) string { /* ... */ }

// С оператором ~ подойдет и string, и любые определённые типы на его основе (например, StringID)
func join[T ~string](values []T, sep string) string { /* ... */ }
```

Оператор `~` — важный нюанс в системе типов Go с дженериками. Без него ограничение `string` требует точного соответствия типа, что означает, что определенный тип `StringID` с подлежащим типом `string`, будет отвергнут компилятором.

Добавляя `~` перед `string`, мы говорим компилятору: "принимай любой тип, у которого подлежащий тип — `string`". Это критично для практического использования, поскольку в реальных приложениях часто используются именованные типы (defined type) для лучшей семантики и безопасности типов, например, `type UserID string` или `type OrderNumber int`.

Этот оператор даёт возможность писать обобщённые алгоритмы, которые работают не только с встроенными типами, но и с пользовательскими типами, построенными на их основе.

### Практический пример: обобщённые коллекции

Дженерики особенно полезны для реализации типобезопасных коллекций:

```go
// Структура с обобщенной мапой
type Repository[K comparable, V any] struct {
    data map[K]V
    mu   sync.RWMutex
}

func NewRepository[K comparable, V any]() *Repository[K, V] {
    return &Repository[K, V]{
        data: make(map[K]V),
    }
}

func (r *Repository[K, V]) Set(key K, value V) {
    r.mu.Lock()
    defer r.mu.Unlock()
    r.data[key] = value
}

func (r *Repository[K, V]) Get(key K) (V, bool) {
    r.mu.RLock()
    defer r.mu.RUnlock()
    value, ok := r.data[key]
    return value, ok
}
```

Этот пример показывает, как создать типобезопасное хранилище объектов с использованием дженериков. `Repository` может работать с любым типом ключа, который удовлетворяет ограничению `comparable` (то есть может использоваться в качестве ключа в map), и любым типом значения.

Такая реализация имеет несколько преимуществ:
1. Полная безопасность типов — компилятор отловит несоответствия типов
2. Не требуется приведение типов при извлечении значений
3. Код переиспользуем для любых подходящих типов без дублирования
4. Потокобезопасность благодаря синхронизации доступа через RW-мьютекс

Без дженериков пришлось бы либо использовать `interface{}` и приведение типов, либо генерировать код для каждой пары типов.

```go
// ...

// Пример использования нашего Repository
type User struct {
    ID   int
    Name string
}

func main() {
    // Создаем репозиторий, где ключ — int, а значение — User
    users := NewRepository[int, *User]()
    
    // Сохраняем пользователя
    users.Set(1, &User{ID: 1, Name: "Alice"})
    
    // Получаем пользователя по ключу с проверкой существования
    if user, found := users.Get(1); found {
        fmt.Println("Found:", user.Name) // Выведет: Found: Alice
    }
    
    // Можем создать репозиторий с другими типами без изменения кода
    orders := NewRepository[string, Order]()
    // ...
}
```

В этом примере мы показываем, как `Repository` может использоваться для хранения и получения объектов `User` по целочисленным `ID`. Благодаря дженерикам тем же типом можно описать и другие варианты - например, `Repository[string, Order]` с совершенно другими типами ключей и значений, используя тот же самый код. Такой универсальный репозиторий с поддержкой разных типов был бы невозможен до Go 1.18 без потери типобезопасности или без прибегания к генерации кода.


### Когда использовать дженерики

Дженерики не являются панацеей. Они добавляют уровень абстракции, который может быть оправдан не во всех случаях. Давайте рассмотрим, когда их использование наиболее целесообразно:

**Используйте дженерики, когда:**
- Вы реализуете алгоритмы или структуры данных, работающие с разными типами (сортировка, поиск, контейнеры)
- Альтернативой было бы дублирование кода или потеря типобезопасности через `interface{}`
- Вам нужна коллекция, сохраняющая информацию о типах на этапе компиляции
- Хотите убрать лишние преобразования к interface{} и избежать связанную потерю производительности

**Избегайте дженериков, когда:**
- Интерфейсы адекватно решают задачу с приемлемой производительностью
- Код становится слишком абстрактным и трудным для понимания
- Увеличение размера бинарного файла критично (компилятор порождает специальные версии кода под каждую используемую комбинацию типов)
- Типы в вашем API могут часто меняться (интерфейсы обеспечивают более гибкую эволюцию чем constraints)

Хорошее эмпирическое правило: если вы замечаете, что пишете одинаковый код для разных типов данных, или вынуждены использовать `interface{}` с последующим приведением типов, — рассмотрите применение дженериков.

## Заключение

В этой лекции мы рассмотрели три ключевых механизма организации кода в Go:

1. **Пакеты** — позволяют структурировать код, определять области видимости и контролировать API. Помните:
   - Экспортируйте только то, что действительно необходимо
   - Используйте `internal` для скрытия деталей реализации
   - Продумывайте структуру модуля заранее так, чтобы избежать циклических зависимостей
   - Продумывайте имена и структуру пакетов с точки зрения пользователя вашего кода

2. **Функции** — основные строительные блоки логики программы:
   - Используйте функциональные опции для гибкой конфигурации
   - Применяйте замыкания для управления состоянием и ресурсами
   - Работайте с ошибками через `errors.Is`, `errors.Join` и оборачиванием контекста через `fmt.Errorf`
   - Создавайте чистые API с предсказуемым поведением и ясной семантикой ошибок

3. **Дженерики** — мощный инструмент для использования обобщённых типов:
   - Позволяют писать типобезопасный код для разных типов данных
   - Используйте их для коллекций и алгоритмов общего назначения
   - Применяйте осмысленные ограничения типов для ясного API
   - Помните о балансе между абстракцией, читаемостью и производительностью

Сочетая эти механизмы, вы можете создавать чистые, поддерживаемые и эффективные проекты на Go, которые легко масштабируются и эволюционируют вместе с вашими потребностями. Модульность пакетов, гибкость функций и типобезопасность дженериков вместе формируют мощный набор возможностей для решения самых сложных задач программирования.

По мере роста вашего проекта, эти механизмы будут помогать поддерживать кодовую базу структурированной и понятной даже при значительном увеличении её размера и сложности.
