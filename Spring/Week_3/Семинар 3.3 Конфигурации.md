## **Задание 1: @Configuration и @Bean**

**Задача:** Создать конфигурацию с ручным определением бинов.

**Решение:**
```java
// 1. Простой класс
public class DatabaseConnection {
    private String url;
    private String user;
    
    public DatabaseConnection(String url, String user) {
        this.url = url;
        this.user = user;
    }
}

// 2. Конфигурация с @Bean
@Configuration
public class AppConfig {
    @Bean
    public DatabaseConnection dbConnection() {
        return new DatabaseConnection("jdbc:h2:mem:test", "admin");
    }
}

// 3. Использование
public class Main {
    public static void main(String[] args) {
        ApplicationContext ctx = new AnnotationConfigApplicationContext(AppConfig.class);
        DatabaseConnection conn = ctx.getBean(DatabaseConnection.class);
        System.out.println("Connection created: " + conn);
    }
}
```

**Вопрос:** Чем отличается `@Bean` от `@Component`?
**Ответ:** `@Bean` используется в методах конфигурационных классов для ручного создания бинов, а `@Component` - для автоматического обнаружения и создания.

## **Задание 2: @Import для модульной конфигурации**

**Задача:** Разделить конфигурацию на модули.

**Решение:**
```java
// 1. Первый модуль
@Configuration
public class DbConfig {
    @Bean 
    public DataSource dataSource() {
        return new SimpleDataSource("jdbc:h2:mem:test");
    }
}

// 2. Второй модуль
@Configuration  
public class ServiceConfig {
    @Bean 
    public UserService userService(DataSource dataSource) {
        return new UserService(dataSource);
    }
}

// 3. Главная конфигурация
@Configuration
@Import({DbConfig.class, ServiceConfig.class})
public class MainConfig {}
```

**Вопрос:** Можно ли импортировать конфигурацию, которая сама импортирует другую?
**Ответ:** Да, Spring рекурсивно обрабатывает все импорты.

## **Задание 3: @DependsOn для управления порядком**

**Задача:** Зависимость между бинами, которые создаются не через DI.

**Решение:**
```java
@Configuration
public class AppConfig {
    @Bean
    @DependsOn("cacheInitializer")
    public UserService userService() {
        System.out.println("Creating UserService");
        return new UserService();
    }
    
    @Bean
    public CacheInitializer cacheInitializer() {
        System.out.println("Initializing cache");
        return new CacheInitializer();
    }
}
// Вывод:
// Initializing cache
// Creating UserService
```

**Вопрос:** Что будет, если создать циклическую зависимость через `@DependsOn`?
**Ответ:** Spring выбросит `BeanCreationException` с сообщением о циклической зависимости.

## **Задание 4: @PropertySource с разными форматами**

**Задача:** Загрузить свойства из нескольких файлов.

**Решение:**
```java
@Configuration
@PropertySource("classpath:app.properties")
@PropertySource(
    value = "file:${CONFIG_DIR}/secrets.properties",
    ignoreResourceNotFound = true
)
public class PropertyConfig {
    @Bean
    public static PropertySourcesPlaceholderConfigurer propertyConfig() {
        return new PropertySourcesPlaceholderConfigurer();
    }
}

// Использование
@Service
public class AppService {
    @Value("${app.name}")
    private String appName;
    
    @Value("${db.password}")
    private String dbPassword;
}
```

**Вопрос:** Какой порядок загрузки property-файлов?
**Ответ:** Последний загруженный файл имеет приоритет при совпадении ключей.

## **Задание 5: @Profile для условной конфигурации**

**Задача:** Разные бины для разных сред.

**Решение:**
```java
@Configuration
public class DataSourceConfig {
    @Bean
    @Profile("dev")
    public DataSource devDataSource() {
        return new SimpleDataSource("jdbc:h2:mem:dev");
    }
    
    @Bean  
    @Profile("prod")
    public DataSource prodDataSource() {
        return new ProductionDataSource("jdbc:mysql://prod:3306/db");
    }
}

// Запуск с профилем:
// java -Dspring.profiles.active=dev -jar app.jar
```

**Вопрос:** Можно ли активировать несколько профилей одновременно?
**Ответ:** Да, через запятую: `-Dspring.profiles.active=dev,debug`.

## **Задание 6: @Order для упорядочивания**

**Задача:** Управление порядком выполнения/создания.

**Решение:**
```java
public interface Validator {
    void validate(String data);
}

@Component
@Order(1)
public class NotEmptyValidator implements Validator {
    public void validate(String data) {
        if (data == null || data.trim().isEmpty()) {
            throw new IllegalArgumentException("Data is empty");
        }
    }
}

@Component  
@Order(2)
public class LengthValidator implements Validator {
    public void validate(String data) {
        if (data.length() > 100) {
            throw new IllegalArgumentException("Data too long");
        }
    }
}

@Service
public class ValidationService {
    @Autowired
    private List<Validator> validators; // Будет отсортирован по @Order
    
    public void validate(String data) {
        for (Validator v : validators) {
            v.validate(data);
        }
    }
}
```

**Вопрос:** Что будет, если не указать `@Order`?
**Ответ:** Без `@Order` бин попадет в конец списка (order = Ordered.LOWEST_PRECEDENCE).
